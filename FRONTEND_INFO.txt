================================================================================
ARQUITECTURA DEL FRONTEND
================================================================================

COMPONENTE PRINCIPAL: App.tsx

Responsabilidades:
  - Gestionar estado del formulario (contacto, vehículo, perfil)
  - Manejar cambios en inputs
  - Comunicarse con API backend (/cotizar)
  - Mostrar resultados de cotizaciones
  - Mostrar errores

Estado (React Hooks):
  - form: FormState (datos del formulario)
  - quotes: Cotizacion[] (resultados de cotizaciones)
  - loading: boolean (estado de carga)
  - error: string (mensajes de error)

Funciones principales:
  - handleContactChange() - Actualizar datos de contacto
  - handleVehicleChange() - Actualizar datos de vehículo
  - handleSubmit() - Enviar formulario y obtener cotizaciones
  - formatCurrency() - Formatear moneda a ARS

Flujo de datos:
  1. Usuario completa formulario
  2. Click en "Cotizar seguro"
  3. handleSubmit() valida y envía POST a http://localhost:3000/cotizar
  4. Espera respuesta con array de Cotizacion[]
  5. Muestra resultados o error

TIPOS DEFINIDOS EN FRONTEND
================================================================================

type TipoPersona = 'F' | 'J'                    # Física o Jurídica
type Genero = 'M' | 'F'                         # Masculino o Femenino
type UsoVehiculo = 'particular' | 'comercial'   # Uso del vehículo

type CotizacionPlan = {
  codigoPlan: string
  nombre: string
  precio: number
  vigencia: string
}

type Cotizacion = {
  aseguradora: string
  numeroCotizacion: string
  fechaCotizacion: string
  planes: CotizacionPlan[]
}

type ContactoForm = {
  dni: string
  nombre: string
  email: string
  telefono: string
}

type VehiculoForm = {
  marca: string
  modelo: string
  anio: string              # NOTA: string en formulario
  esOkm: boolean
  uso: UsoVehiculo
  valorVehiculo: string     # NOTA: string en formulario
  codigoPostal: string
  provincia: string
}

type FormState = {
  contacto: ContactoForm
  vehiculo: VehiculoForm
  tipoPersona: TipoPersona
  genero: Genero
}

================================================================================
COMUNICACIÓN CON BACKEND
================================================================================

Endpoint: POST http://localhost:3000/cotizar

Request:
  - Headers: Content-Type: application/json
  - Body: FormState completo
  - Payload:
    {
      contacto: { dni, nombre, email, telefono },
      vehiculo: { marca, modelo, anio: number, esOkm, uso, valorVehiculo: number, codigoPostal, provincia },
      tipoPersona: 'F' | 'J',
      genero: 'M' | 'F'
    }

Response esperada:
  - Status 200: Cotizacion[]
  - Status error: { error: string }

Manejo de errores:
  - Try-catch en handleSubmit()
  - Muestra error en UI si falla
  - Loading state durante la request

================================================================================
PROBLEMAS IDENTIFICADOS
================================================================================

1. ❌ SIN VALIDACIÓN DE DATOS
   - No valida formato de email, DNI, teléfono
   - No valida rangos de años, valores de vehículo
   - Solo relying en HTML required attribute

2. ❌ ENDPOINT HARDCODEADO
   - URL de API está hardcodeada en el código
   - No hay separación de ambientes

3. ❌ TIPOS INCONSISTENTES
   - Usa strings en formulario, luego convierte a números
   - Mejor tipado sería más seguro

4. ❌ SIN CANCELACIÓN DE REQUESTS
   - Si navega away durante request, continúa corriendo
   - Potencial memory leak

5. ❌ SIN ERROR TYPING
   - Error es string, mejor sería union type discriminado
