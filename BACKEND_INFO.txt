================================================================================
ARQUITECTURA DEL BACKEND
================================================================================

PATRÓN: Arquitectura en capas con Adapter Pattern

    ┌─────────────┐
    │   Routes    │  ← Maneja HTTP requests/responses
    └──────┬──────┘
           │
    ┌──────▼──────────┐
    │   Services      │  ← Lógica de negocio
    └──────┬──────────┘
           │
    ┌──────▼──────────┐
    │   Adapters      │  ← Integración con aseguradoras
    └─────────────────┘

FLUJO DE REQUEST:
1. Cliente envía POST /cotizar con datos
2. Route cotizar.routes.ts recibe request
3. Valida datos (actualmente sin validación)
4. Llama a obtenerCotizaciones() en service
5. Service ejecuta adapters en paralelo
6. Cada adapter devuelve cotización
7. Response se devuelve al cliente

app.ts - CONFIGURACIÓN EXPRESS
────────────────────────────────
Responsabilidades:

  - Configurar middlewares (CORS, JSON parser)
  - Registrar rutas

Código:

  app.use(cors())  // ⚠️ CORS abierto sin restricciones

  app.use(cotizarRouter)

Configuración actual:
  - CORS: Acepta cualquier origen (*)
  - Body parser: Acepta JSON
  - Rutas: Carga router de cotizaciones

services/cotizacion.service.ts - LÓGICA DE NEGOCIO
─────────────────────────────────────────────────
Responsabilidades:
  - Coordinar múltiples adapters
  - Manejar errores de forma robusta
  - Procesar resultados

Función principal:
  obtenerCotizaciones(datos: DatosAuto): Promise<Cotizacion[]>

Implementación:
  1. Define array de adapters (3 aseguradoras mock)
  2. Ejecuta todos en paralelo con Promise.allSettled()
  3. Filtra solo resultados exitosos
  4. Retorna array de cotizaciones

Ventajas del allSettled():
  - ✓ No falla si una aseguradora no responde
  - ✓ Devuelve las que sí funcionaron
  - ✓ Mejor UX que esperar a todas

Adapters actuales:
  1. Aseguradora Norte - precio base: 40000 ARS
  2. Aseguradora Sur - precio base: 55000 ARS
  3. Aseguradora Centro - precio base: 48000 ARS

adapters/types.ts - DEFINICIÓN DE INTERFAZ
──────────────────────────────────────────

Interfaz:

Propósito:

================================================================================
FLUJO COMPLETO DE REQUEST
================================================================================

1. CLIENTE (Frontend)
   ├─ Completa formulario
   └─ Envía POST /cotizar con body

2. SERVIDOR (Express)
   ├─ Route handler en cotizar.routes.ts
   ├─ Recibe request
   ├─ Cast a DatosAuto
   └─ Llama a obtenerCotizaciones()

3. SERVICE
   ├─ Crea array de 3 adapters
   ├─ Ejecuta Promise.allSettled()
   │  ├─ Adapter 1: Simula latencia, genera cotización
   │  ├─ Adapter 2: Simula latencia, genera cotización
   │  └─ Adapter 3: Simula latencia, genera cotización
   ├─ Espera a todas (max ~1000ms)
   └─ Filtra exitosas y devuelve

4. RESPONSE
   ├─ Status 200
   └─ Body: Cotizacion[]

5. CLIENTE (Frontend)
   ├─ Recibe array de cotizaciones
   └─ Renderiza resultados

================================================================================
PROBLEMAS IDENTIFICADOS
================================================================================

🔴 CRÍTICOS:
  1. ❌ SIN VALIDACIÓN DE REQUEST
     - No valida estructura de DatosAuto
     - No valida rangos de valores
     - No valida formatos (email, teléfono, DNI)
     → Riesgo: Datos inválidos procesados

  2. ❌ CORS MUY ABIERTO
     - app.use(cors()) sin opciones
     - Acepta cualquier origin
     → Riesgo: Vulnerabilidad CSRF

  3. ❌ SIN ERROR TYPING
     - Error es string genérico
     - No diferencia tipos de error
     → Impacto: Frontend no sabe qué pasó

🟡 IMPORTANTES:
  1. ❌ SIN LOGGING ESTRUCTURADO
     - Solo console.error()
     - Difícil debuggear en producción

  2. ❌ SIN VALIDACIÓN DE RESPONSE
     - Los adapters pueden devolver datos inválidos
     - Sin verificación de schema

  3. ❌ MOCK ADAPTERS HARDCODEADOS
     - Precios fijos
     - No hay forma de agregar nuevos

🟢 MENORES:
  1. ✓ Variables de ambiente incompletas
  2. ✓ Sin versionado de API (/v1/cotizar)

CÓMO EXTENDER CON NUEVOS ADAPTERS
================================================================================

Paso 1: Crear nuevo archivo en adapters/
  adapters/real/seguros-argentina.adapter.ts

Paso 2: Implementar la interfaz QuoteAdapter
  export function crearSegurosArgentinaAdapter(): QuoteAdapter {
    return {
      async cotizar(datos: DatosAuto): Promise<Cotizacion> {
        // Lógica: llamar a API real
      }
    }
  }

Paso 3: Agregar a servicio
  // En cotizacion.service.ts
  import { crearSegurosArgentinaAdapter } from '../adapters/real/...'

  const adapters: QuoteAdapter[] = [
    // ... existentes
    crearSegurosArgentinaAdapter()
  ]

¡Listo! Service automáticamente lo ejecutará en paralelo.
